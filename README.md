# 차이나타운 골목탐정

**그림 지도와 사진 힌트로 장소를 찾고, 그 자리에서 4지선다 문제를 푸는 모바일 골목 탐험 게임**입니다. Agent Field Trip 2026: Incheon에서 수집한 사진과 현장 관찰을 게임의 단서·정답 근거로 연결합니다.

**[골목탐정 플레이하기](https://ezid007.github.io/GDG_Incheon/)** — GitHub Pages에서 제공하므로 개발 노트북이 꺼져 있어도 접속할 수 있습니다.

2026-09-12 현재 소스는 `field-v2`입니다. **인화문 현판을 묻는 실제 미션 1개**를 반영했으며, 이번 변경의 CI·공개 배포 확인은 대기 중입니다. 기존 가상 예시 3개는 실제 문제가 없는 구역의 시연 자료로 보존합니다.

## 어떻게 플레이하나요?

한 장소를 찾고 관찰하는 **2단계 미션**입니다. 서로 다른 장소 두 곳을 방문하는 방식이 아닙니다.

1. **1차 · 장소 찾기:** ‘1차 퀴즈 시작하기’를 누르고 [그림 지도](https://ezid007.github.io/GDG_Incheon/map.html?region=chinatown)의 넓은 탐색 구역과 크롭 사진 힌트로 장소를 찾습니다.
2. **2차 · 현장 퀴즈:** ‘장소를 찾았어요 → 2차 퀴즈’를 누르고, 실제 장소의 현판을 살펴본 뒤 4개 선택지 중 하나를 고릅니다.
3. **정답 확인:** 틀리면 다시 선택하고, 맞히면 관문 전체 사진·정답 근거·해설을 확인합니다.
4. **완료:** 발견 기록을 확인합니다. 현재 실제 미션은 1개이며, 같은 탭의 새로고침과 다시 시작을 지원합니다.

전체 정답 사진은 장소 찾기나 힌트에 사용하지 않고 **정답을 맞힌 뒤** 공개합니다. 회원가입이나 앱 설치는 필요하지 않습니다.

## 지도와 시연

지도는 실제 도로 좌표를 그림처럼 단순화하고 정답 위치 대신 **넓은 탐색 구역**을 보여줍니다. A 차이나타운 남쪽은 실제 미션과 연결되며, B 동화마을은 문제 연결 준비용 구역입니다.

휴대전화에서 ‘내 위치 확인’을 누르면 위치 접근 허용 후 현재 위치와 오차 범위를 한 번 표시합니다. 위치는 저장하거나 서버로 보내지 않습니다. 지도 밖·큰 오차·오래된 위치에는 잘못된 점을 표시하지 않으며 실제 현장 휴대전화의 정확도는 추가 확인이 필요합니다.

**GPS로 도착을 인증하거나 문제를 잠그지 않습니다.** 플레이어가 장소를 찾았다고 판단하면 직접 2차 퀴즈로 넘어갑니다.

발표에서는 지도 아래의 **‘시연: 도착했어요 → 2차 퀴즈’** 또는 [차이나타운 도착 시연](https://ezid007.github.io/GDG_Incheon/?demo=arrival&region=chinatown)을 이용합니다. 현장에 가지 않고 2차 퀴즈를 체험할 수 있으며, 화면에 시연 표시를 유지하고 일반 플레이와 기록을 분리합니다. 선택한 구역의 실제 문제가 없으면 예시 3개를 사용합니다.

## 로컬 실행

검증 환경은 Node.js 22/24입니다. 별도 패키지 설치 없이 저장소 루트에서 실행합니다.

```sh
node apps/golmok-detective/build.mjs
node apps/golmok-detective/serve.mjs
```

브라우저에서 [http://127.0.0.1:4179](http://127.0.0.1:4179)를 엽니다. 다른 포트는 다음처럼 지정합니다.

```sh
node apps/golmok-detective/serve.mjs --port 4180
```

`127.0.0.1` 주소는 서버를 실행한 컴퓨터에서만 열립니다. 휴대전화에서는 공개 HTTPS 주소를 사용합니다. 수정 반영과 운영 조건은 [공개 운영 안내](docs/deployment.md)에 있습니다.

## 문제 작성과 배포

팀원 문제 원본은 `apps/golmok-detective/data/quiz.js`입니다. `load-quiz.mjs`가 질문·보기·사진 경로를 읽고 `data/quiz-support.json`의 검수 정보·예시와 결합합니다. 사진, 질문, 선택지 4개, 정답, 근거, 넓은 탐색 구역을 [미션 작성 양식](docs/mission-authoring.md)에 맞춰 전달합니다. 실제 문제는 4지선다, 보존한 가상 예시는 3지선다입니다. 코드나 자료를 수정하면 게임과 지도를 다시 빌드합니다.

팀원 문제 원본은 `python/quiz_class_sample.py`이며, 기존 `raw/missions/`·`wiki/` 자료는 [커밋 096c7fc](https://github.com/ezid007/GDG_Incheon/tree/096c7fc)의 기록으로 남아 있습니다. 게임은 검수해 복사한 `public/assets/` 사진을 사용합니다. 인화문 미션은 사진의 실제 현판과 선택지를 대조해 반영했으며, 기존 초안의 다른 관문 이름·역사 설명은 가져오지 않았습니다. [현장 미션 검수 기록](docs/field-missions.md)에 정답 근거와 사진의 사용 시점을 기록합니다.

팀원은 `main`에 게임 코드를 푸시하면 테스트·빌드 후 자동 배포할 수 있습니다. 수동 실행은 GitHub Actions → **Deploy Golmok Detective → Run workflow → main**입니다. Pages 설정 변경은 개인 저장소 소유자가 담당합니다.

## 검증 상태

```sh
node --test apps/golmok-detective/tests/*.test.mjs
```

2026-09-12 현재 로컬의 상태·지도·미션·세션 검사 **59개가 통과**했습니다. 서버를 포함한 전체 검사는 **68개 중 66개 통과, 2개 실패**입니다. 두 실패는 기존 로컬 AdGuard의 HTML 헤더 변경·HEAD 응답 파싱 문제이며, 실패를 숨기거나 검사를 건너뛰지 않았습니다. **이번 버전의 CI 실행·공개 배포 확인은 대기 중**입니다.

초기 예시 버전에서는 GitHub Actions 21개 검사와 3미션 완주·오답·힌트·확대·복원·반응형 화면·공개 HTTPS 접속을 확인했습니다. 이는 이전 버전의 검증 기록이며, 현재 버전에서는 2차 정답 사진·완료·새로고침 복원, 시연 정답 후 복원·일반 루트와의 분리, 320·390·1280px 게임·지도 가로 넘침 없음을 확인했습니다. 최신 검증과 남은 항목은 [구현·협업 안내](docs/implementation.md)에 기록합니다.

## 동료가 참여할 부분

- **현장 관찰:** 직접 찍은 사진, 장소 이름, 관찰한 특징을 정리합니다.
- **문제 작성:** 현장에서 확인할 질문·선택지·정답 근거를 작성합니다. 장소를 찾는 사진과 정답 확인 사진을 구분합니다.
- **제작과 확인:** 미션 데이터를 반영하고 휴대전화에서 1차 탐색부터 2차 퀴즈·완료까지 검사합니다.
- **발표 준비:** 현장 관찰이 기능에 연결된 이유, 사람별 역할과 Agent 활용, 실제 플레이와 시연 화면을 준비합니다.

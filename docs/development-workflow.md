# 다음 작업을 위한 개발 가이드

확인일: 2026-09-13 · 적용: 현재 골목탐정 정적 웹 구조

## 한 번에 하나의 작업

먼저 [루트 PLAN](../PLAN.md)에 목적·수정 범위·검증 방법을 적습니다. 진행 중 항목은 하나만 두고, 작업이 끝나면 결과와 남은 제한을 기록합니다. 기능 추가, 자료 정리, 공개 배포를 같은 완료 상태로 묶지 않습니다.

작업 요청은 다음처럼 작게 나누면 검토하기 쉽습니다.

```text
목적: 공유 창에서 QR 아래 설명을 읽기 쉽게 바꾸기
수정 범위: game.html의 설명, game.css의 모바일 여백
유지할 것: QR 원본, 복사 URL, 문제·진행 기록
검증: 320/390px 화면, 주소 복사, 닫기·초점 복귀
완료: 빌드·검사 결과와 변경 파일을 기록
배포: 별도 재개 요청 전에는 하지 않음
```

## 무엇을 어디서 고칠까

경로는 `apps/golmok-detective/` 기준입니다.

| 바꾸려는 것 | 작업 위치 |
|---|---|
| 게임 구조·기본 문구 | `src/pages/game.html` |
| 지도 화면 구조·문구 | `src/pages/map.html` |
| 색상·크기·배치·모바일 대응 | `src/styles/game.css`, `map.css` |
| 클릭·모달·공유·표시 처리, 모드별 문구 | `src/scripts/game.js` |
| 지도 선택·확대·위치 요청 | `src/scripts/map.js` |
| 정답·힌트·완료·저장 복원 규칙 | `game-state.mjs` |
| 문제별 URL·일반/시연 기록 | `demo-session.mjs` |
| 좌표 변환·위치 오차 판정 | `location.mjs` |
| 새 문제·사진 역할·선택지·정답 | `data/quiz-support.json` |
| 사진 추가·교체 | `public/assets/quiz/<문제>/` |
| 지도 도로·탐색 범위 | `data/map-geography.json`, `exploration-map.json` |
| 페이지 조립·사진 내장 | `build.mjs`, `build-map.mjs`, `build-page.mjs` |

`public/index.html`과 `public/map.html`은 직접 수정하지 않습니다. 원본을 고친 뒤 빌드해야 다시 생성해도 변경이 유지됩니다. 생성 HTML을 하나의 파일로 제공하는 방식은 유지하되, 사람이 편집하는 소스는 HTML·CSS·JS로 나눕니다.

문구를 고칠 때는 같은 문장을 소스에서 검색합니다. 소개·현장·시연 모드에 따라 바뀌는 문구는 `game.js`의 `configureIntro`, `configureFieldMode`, `configureDemoMode` 같은 설정 함수가 덮어쓸 수 있으므로 해당 모드 화면에서 결과를 확인합니다.

## 파일을 늘리기 전에

1. 같은 역할의 코드·자료가 있는지 찾고 기존 위치를 먼저 사용합니다.
2. 문제 사진은 장소 찾기·질문·정답의 역할과 실제 내용을 확인합니다. 동일 사진을 `hint`, `quiz`, `final` 같은 이름으로 여러 번 복사하지 않습니다.
3. 사용 중인 사진만 `public/assets/`에 넣습니다. 미사용 원본은 `reference/`, 공유 제외 자료는 `docs/private/`, 임시 실험은 `work/`에 둡니다.
4. 원본 첨부·참고 자료를 삭제하는 대신 보관 위치와 이유를 기록합니다. 이동 후 참조 경로도 확인합니다.
5. 새 라이브러리는 기존 표준 모듈로 해결되는지 검토하고, 프로덕션 의존성 추가는 사전 확인합니다.

현재 런타임 패키지 설치는 필요 없습니다. `.editorconfig`의 UTF-8·LF·공백 2칸과 앱 `.prettierrc.json`의 형식을 따릅니다. `src/scripts/`는 브라우저에서 조립되는 코드이므로 패키지나 import를 추가할 때 빌드 방식을 함께 검토합니다.

## 검증 순서

저장소 루트에서:

```sh
node apps/golmok-detective/build.mjs
node --test apps/golmok-detective/tests/*.test.mjs
node apps/golmok-detective/serve.mjs
```

기본 미리보기는 `http://127.0.0.1:4179/`입니다. 다른 서버가 사용 중이면 `--port 4184`처럼 포트를 지정합니다. 빌드 후 새로고침하며, 검사 실패를 기존 문제라고 단정하지 않고 이번 변경과 원인을 구분합니다.

변경한 영역을 먼저 확인하고 다음 흐름으로 회귀를 확인합니다.

- 첫 안내 → 세로 목록 → 장소 찾기 사진 → 도착 → 2차 질문 → 오답 → 정답 사진·해설 → 목록 복귀.
- 피노키오의 1차 사진·2차 파란 무늬·정답 5개가 바뀌지 않았는지.
- 일반·시연 진행이 섞이지 않고 새로고침 복원이 유지되는지.
- 320/390px의 가로 넘침·이미지·보기·모달과 키보드 닫기·초점.
- 공유 QR과 복사 주소, 지도 선택·확대, 위치 거부·범위 밖 안내.

로컬에서 확인한 화면과 실제 현장 GPS 검증을 구분합니다. 빌드·단위 검사만 통과했다고 모바일 화면까지 확인했다고 기록하지 않습니다.

## 여러 사람이 작업할 때

먼저 파일 담당을 나눕니다. 같은 JSON이나 같은 화면 스크립트를 동시에 수정해야 한다면 한 사람이 통합하고, 다른 사람은 입력 내용·검수 결과를 전달합니다. 소스 변경과 함께 생성 HTML을 매번 서로 편집하지 않습니다.

변경을 반영할 저장소와 작업 브랜치를 확인합니다. 관련 변경만 묶어 검증한 뒤 커밋·동기화하고, 충돌은 원본 소스와 데이터의 의도를 대조해 해결합니다. 생성 HTML에 충돌이 나면 소스부터 해결하고 다시 빌드합니다. 강제 푸시나 타인의 작업 되돌리기는 일반 충돌 해결 방법으로 사용하지 않습니다.

루트 AGENTS의 fetch·rebase·커밋·푸시 절차를 따릅니다. 최종 검증은 소스와 데이터를 통합한 상태에서 수행합니다.

## 자동 검사와 배포를 분리

`.github/workflows/check.yml`은 main 푸시·PR의 앱 변경에 빌드·검사만 수행합니다. 배포 권한이나 배포 작업은 없습니다.

`deploy-pages.yml`은 수동 실행만 가능하고 현재 비활성화돼 있습니다. 검사 성공이나 커밋·푸시는 공개 허가를 뜻하지 않습니다. 배포를 재개할 때 [실행·배포 문서](deployment.md)의 완료 기준을 따릅니다.

## 문서를 현재 상태로 유지

공유 문서는 작업 목적·기능·구현 변경·실행 방법·검증 결과·기술적 제한으로 한정합니다. 개인별 기여, 대화와 개인 지시, 제작 도구 사용 이력, 계정 및 개인 환경은 기록하지 않습니다. 이 기준은 README, PLAN, 보관 문서에도 동일하게 적용합니다.

- README: 게임 소개·실행·문서 진입점. 배포 상태 변화와 긴 작업 일지를 계속 붙이지 않습니다.
- 루트 PLAN: 현재 작업과 남은 항목만 관리합니다.
- `docs/`: 현재 구조·규칙·제약을 수정합니다. 과거 내용 뒤에 새 문단만 덧붙여 모순을 남기지 않습니다.
- `docs/archive/`: 의미 있는 이전 기록을 날짜별로 보존합니다.
- `logs/development.log`: 시간·목적·파일·변경 이유·검증 결과를 추가합니다. 비밀 값은 기록하지 않습니다.

마지막 보고에는 변경 내용, 유지한 동작, 실행한 검사, 확인하지 못한 항목, 문서 위치를 포함합니다. “작동한다”보다 어디까지 확인했는지 구체적으로 적습니다.

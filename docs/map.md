# 그림 지도와 대략 위치 탐색

확인일: 2026-09-12 · 현재 작업 버전: `scroll-pinocchio-v1` · 브라우저 표준 Geolocation API · 새 패키지/SDK 없음 · 새 세로 화면·사진 역할·공개 배포 검증 대기

## 현재 동작

차이나타운·송월동 동화마을의 실제 도로를 **공용 SVG 그림 지도1개**로 단순화했다. 검수한 실제 문제2개의 카드를 모두 세로로 나열해 아래로 스크롤하며 볼 수 있게 한다. 가로 문제 전환 탭과 지역 탭은 사용하지 않는다. 각 카드의 장소 찾기 사진과 넓은 탐색 범위를 보고 찾아간 뒤, 해당 카드의 도착 버튼으로 같은 문제의2차 사진·4지선다를 연다.

| 실제 문제 목록 | 현재 상태 | 탐색 범위 |
|---|---|---|
| 문제 1 · `inhwamun-plaque` | 검수한 실제 현장 4지선다 1개 | 기본값은 한중문화관 대표점을 중심으로 반경135m |
| 문제 2 · `pinocchio-clouds` | 파란 계열 무늬5개를 묻는 실제 문제 | 기존 송월동 동화마을 대표점 주변 반경110m, 정밀 촬영 좌표 아님 |

실제 목록에는 문제2개를 넣고 가상 예시3개는 제외한다. 문제1은 금빛 조각상 부분 사진, 문제2는 **피노키오와 하트가 보이는 최초 Photo1 크롭 사진**으로 장소를 찾는다. 문제2의 최초 Photo3 파란 무늬 확대 사진은 도착 후2차 문제에서만 사용한다. **2차 사진과 정답 확인 사진은 지도에 내장하지 않으며 정답 사진은 맞힌 뒤 공개한다.** 파란 확대 사진을 먼저 장소 찾기 단서로 사용하던 이전 역할은 사용자 지시로 대체했다.

- `map.html` 하나에 지도·문제별 탐색 범위·사진 단서·위치 처리 코드를 모두 내장한다. 플레이 중 외부 지도 타일/API를 호출하지 않는다.
- 지도 확대/축소/전체 보기와 손가락·스크롤 이동을 제공한다. 모든 실제 문제 카드는 세로로 펼치고 카드마다 해당 문제의 도착·시연 링크를 둔다.
- 북쪽이 위다. 도로 좌표와 사용자 위치에 같은 투영식을 사용한다.
- **내 위치 확인**을 눌렀을 때 한 번만 위치를 요청한다. 자동 추적·백그라운드 수집·위치 저장·서버 전송 없음.
- 정상 위치는 파란 점과 예상 오차 타원으로 표시한다. 1분이 지나면 점을 숨기고 재확인을 안내한다.
- 지도 범위 밖, 100m 초과 오차, 오래된 값, 잘못된 좌표는 점을 표시하지 않는다. 지도 가장자리로 임의 보정하지 않는다.
- HTTPS·사용자 위치 권한이 필요하다. 거부, 위치 조회 불가, 15초 조회 제한, 권한창을 포함한 20초 UI 대기 제한과 재시도를 제공한다.
- 위치 확인은 탐색을 돕는 선택 기능이다. GPS 인증을 강제하지 않으며 위치로 정답을 열거나 실제 도착을 인증하지 않는다. 도로의 현재 출입 가능 여부와 안전한 이동은 현장 안내를 따른다.

## 현장 진행과 발표 시연

하나의 문제는 `장소 찾기 사진·넓은 탐색 범위 → 카드의 도착 버튼 → 2차 사진·4지선다 → 정답 해설` 순서다. 실제 퀴즈 화면에서도 사진 다음에 질문·보기가 세로로 이어진다. 정답 후 다음 문제가 있으면 그 문제의 장소 찾기로 이동하고, 마지막 문제라면 세로 문제 목록으로 돌아간다. 현장 진행과 발표 시연은 서로 다른 링크와 기록을 사용한다.

| 사용 목적 | 지도 버튼 / 주소 | 동작 |
|---|---|---|
| 1차 장소 찾기 | `map.html?quiz=inhwamun-plaque` | 같은 지도에서 선택한 문제의 범위와 부분 사진을 표시한다. |
| 실제 현장 진행 | **장소를 찾았어요 → 2차 퀴즈**, `./?play=field&quiz=inhwamun-plaque` | 도착을 스스로 확인하고 그 문제의 2차 퀴즈를 연다. GPS 성공 여부와 무관하다. |
| 발표 시연 | **시연: 도착했어요 → 2차 퀴즈**, `./?demo=arrival&quiz=inhwamun-plaque` | 실제 방문 없이 도착을 가정한다는 시연 안내와 함께 같은 문제를 연다. |

각 문제 카드의 사진·안내·현장/시연 링크는 같은 문제 ID를 가리킨다. 다른 카드를 보기 위해 가로 전환 버튼을 누르지 않고 아래로 스크롤한다. 도착/시연 버튼은 가짜 GPS 점이나 도착 인증 기록을 만들지 않는다. 예전 `region` 주소는 호환용으로 처리할 수 있지만 새 화면과 공유 링크는 `quiz`를 사용한다. 내부 지역 분류를 사용자에게 다시 선택하게 하지 않는다.

`demo-session.mjs`는 문제 ID와 현장/시연 모드별로 진행 기록을 분리한다. 한 문제의 시연 결과가 다른 문제나 실제 플레이의 완료 기록에 합쳐지지 않는다. 빌드 시 검수한 `sceneKind: "field"` 문제만 순서대로 `MAP.quizzes`에 구성한다. `explorationRegionId`와 기존 대표 좌표는 지도 배치에만 사용하며 사용자용 지역 필터가 아니다.

미션에 선택 항목 `explorationArea: { latitude, longitude, radiusMeters }`를 지정하면 그 문제의 검수한 탐색 범위로 기본값을 덮어쓴다. 생략하면 기존 `explorationRegionId`의 대표 영역을 사용한다. 이는 넓은 탐색 범위이며 정확한 정답 핀이나 GPS 도착 조건이 아니다.

| 위치 요청 조건·옵션 | [MDN getCurrentPosition](https://developer.mozilla.org/en-US/docs/Web/API/Geolocation/getCurrentPosition) |

화면에는 OSM 저작권과 인천투어 링크를 표시한다. 지리 데이터 원본 범위는 서126.615 / 남37.472 / 동126.627 / 북37.481, 화면은 그 안의 **서126.615 / 남37.472 / 동126.624 / 북37.4805**이다. 인화문 주변을 포함하도록 화면의 남쪽 범위를 확장했다. bbox 밖으로 이어지는 도로는 SVG clipPath로 자른다. `foot=no`, 일반 `access=no/private` 도로는 표시 대상에서 제외하되 `foot=yes` 예외를 고려한다. 이 필터가 현장의 통행 가능 여부를 보증하지는 않는다.

인화문 문제의 기본 중심은 정답 핀이 아닌 한중문화관의 공식 대표점이다. 팀 미션에는 위도37.473045, 경도126.6188592가 함께 전달되었고 문화관 인근임을 대조했지만 문의 정확한 좌표라는 사실은 확인되지 않았다. GPS 도착 인증에 사용하지 않는다. 피노키오 문제의 기본 동화마을 대표점은 위도37.4782594659769, 경도126.619971883104이며 정확한 입구나 사진 촬영 위치를 뜻하지 않는다. 새 정밀 GPS 좌표를 만들지 않고 반경110m의 넓은 탐색 범위를 사용한다.

## 파일과 설정

- `apps/golmok-detective/map.template.html`: 공용 지도1개·세로 문제 카드 전체·장소 찾기 사진·위치 조회·카드별 현장/시연 링크.
- `build-map.mjs`: 지리 데이터를 SVG로 만들고 검수한 현장 문제 순서의 `MAP.quizzes`, 문제별 탐색 범위와 부분 사진을 HTML에 내장. 2차 문제·정답 전체 사진은 지도에 넣지 않음.
- `demo-session.mjs`: 문제별 현장/시연 선택, 예전 주소 호환 처리, 진행 기록 분리.
- `location.mjs`: 위경도→그림 좌표, 유효성·오차·시간 검사.
- `data/map-geography.json`: OSM 데이터와 공식 대표점, 출처·라이선스.
- `data/exploration-map.json`: 지도 bounds와 내부 대표 영역의 좌표·반경·출처. 지역 탭이나 실제 문제 목록을 직접 만들지 않는다.
- `data/quiz.js`, `data/quiz-support.json`, `load-quiz.mjs`: 팀원 문제 원본과 검수 정보에서 `sceneKind`, `explorationRegionId`, 선택적인 `explorationArea`, 부분 사진 `image` 등을 구성한다. 지도에는 2차 `quizImage`·`answerImage`를 포함하지 않는다.
- `public/map.html`: 배포 산출물. 직접 수정하지 않고 원본을 빌드한다.

```sh
node apps/golmok-detective/build.mjs
node --test apps/golmok-detective/tests/*.test.mjs
```

위치 처리 예시:

```js
const result = assessLocation(position, map.bounds, map.width, map.height);
if (result.status === 'ready') {
  // x/y에 점, radiusX/radiusY에 오차 타원을 표시한다.
}
```

차이나타운 대표 영역135m·동화마을 대표 영역110m와 100m 위치 오차 한계는 MVP 초기 설정이다. 실제 스마트폰과 현장 동선으로 조정하며, 문제마다 검수한 `explorationArea`가 있으면 해당 범위를 우선한다. 위치 접근 자체에 모델 API·지도 API 키를 쓰지 않는다. 단순 정적 웹이므로 정답의 화면 공개 시점을 제어하는 것이며, 배포 파일 자체를 열람할 수 없도록 숨기는 구조는 아니다.

## 검증과 남은 확인

`scroll-pinocchio-v1`의 검증은 대기 중이다. 공용 지도1개와 실제 카드2개가 세로 스크롤로 모두 표시되는지, 카드별 도착/시연 링크가 맞는지, 첫 사진이 피노키오·하트이고 도착 후 사진이 파란 무늬인지, 정답 후 최신 벽면 사진을 보여주는지 확인한다. 새 템플릿·자동 검사·작은 화면·공개 배포 결과를 확인한 뒤 갱신한다. 현장 GPS 정확도는 여전히 미검증이다.

### 이전 단일 지도 버전의 검증 이력

`unified-v1` 코드 `f12fe15`의 **CI 72개 검사·빌드·배포가 모두 성공**했다. [이번 GitHub Actions 기록](https://github.com/ezid007/GDG_Incheon/actions/runs/34673092862) 로컬 지도 검사18개·세션 검사10개가 모두 통과했고, 로컬 전체는72개 중70개 통과·기존 AdGuard 헤더/HEAD 관련2개 실패였다. 공개 Chrome에서 A/B 탭 없이 문제1과 선택된 탐색 원이 표시되고, 도착→가림 사진·4지선다→정답 원본→완료→문제 목록으로 연결됨을 확인했다. 시연은 별도0/1 진행을 유지했다. 로컬320·1280px와 공개390px에서 가로 넘침이 없었으며 실제 휴대전화의 현장 위치 정확도는 아직 미검증이다.

다음 결과는 **이전 `field-v2`와 그 이전 버전의 검증 이력**이다.

- 순수 위치 함수 13개: 모서리·중심·범위 밖·정확도 경계·잘못된 값·만료·불변성 통과.
- 이전 지도 UI 14개: 실제 산출물 스크립트를 Node VM의 테스트 DOM/시계/위치 fixture로 실행. 성공·거부·미지원·시간 초과·큰 오차·범위 밖·1분 만료·늦은 응답 무시·당시 구역 링크 일치에 더해, 실제 미션 구역에서만 사진/현장 링크가 표시되는지와 지도에 정답 전체 사진을 내장하지 않는지 검사했다.
- 브라우저: 기존 320px·390px·PC에서 구역 전환·확대·전체 보기와 페이지 가로 넘침 없음을 확인했다. 현장 링크·사진 단서를 포함한 최종 화면과 공개 주소도 확인했다. 실제 휴대전화 핀치·현장 GPS 점의 정확도는 미검증.
- 테스트 좌표는 검사 안에서만 사용하며 서비스에는 가짜 GPS 위치를 넣지 않는다. 발표용 버튼도 위치 데이터와 별개다.
- 이전 로컬 전체 검사에는 AdGuard HTTP 변조 때문에 헤더/HEAD 검사 2건이 실패했다. 당시 순수 상태·지도·미션 검사는 별도 통과했고 `field-v2` CI에서는 전체68개 검사가 통과했다. 이번 버전의 결과로 간주하지 않는다.

## 이전 사진 지도

사용자 안내판 사진은 원본 자료로 보존했다. 기울어진 관광안내도는 축척·도로 위치가 왜곡되어 GPS 좌표를 바로 얹지 않는다. 이전 사진 확대 HTML은 로컬 기록에 보존하고 현재 공개 지도는 실제 도로 SVG로 교체했다. 생성 이미지의 잘못된 지명 문제를 피하기 위해 이번에는 새 이미지 생성 없이 실제 좌표와 코드로 그렸다.

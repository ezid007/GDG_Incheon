전체 사진은 힌트·탐색 지도·도착 전 안내에 쓰지 않는다. 문제 사진의 대체 설명과 힌트에도 정답 이름을 먼저 적지 않았다. 힌트는 현장에서 시선을 돌릴 부분만 안내한다. `evidence: { "x": 48.5, "y": 44.5 }`는 **정답 확인용 전체 사진**에서 현판 중심을 표시하는 백분율이며, 문제 사진의 좌표나 GPS 좌표가 아니다.

정답 데이터와 사진은 정적 웹 배포 파일에 포함된다. 화면상 공개 시점을 구분하는 체험 게임이며, 소스 확인에 대한 정답 비밀 보장을 제공하지 않는다.

## 좌표의 출처와 범위

```json
{
  "explorationRegionId": "chinatown",
  "geoCoordinates": {
    "latitude": 37.473045,
    "longitude": 126.6188592
  }
}
```

좌표는 팀원 자료의 `geo_coordinates`를 그대로 옮긴 참고 메타데이터다. 관문 위치를 현장에서 정밀 측량한 값으로 검증한 것은 아니다. 한중문화관 인근을 포함하는 **넓은 탐색 구역의 중심을 잡는 용도**로만 사용하며, 정확한 정답 핀·도착 인증·자동 정답 해제로 사용하지 않는다. 사용자에게는 구역 안에서 사진의 조각상을 직접 찾아보도록 안내한다.

## 팀원 문제 소스 통합

팀원의 정리 커밋에 따라 `missions.json`은 사용하지 않는다. `load-quiz.mjs`는 `quiz.js`의 질문·선택지·좌표를 읽고 `quiz-support.json`의 검수 정보(단서/문제/정답 사진 설명·해설·근거 좌표·검수 정답)와 결합한다. 팀원 형식의 `correctAnswerIndex`는 1부터 시작하는 보기 번호로 해석하고, 해당 보기의 글자가 검수 정답과 같은지 확인한다. 원본 세 사진과 공개 복사본이 다르거나 새 문제가 아직 검수 목록에 없으면 빌드를 중단한다. 사진 이름만으로 힌트 공개 여부를 결정하지 않는다.

## 단일 지도 통합 · unified-v1

출제자가 제공한 질문·네 선택지·사진·정답은 유지한다. 차이나타운과 동화마을을 따로 고르는 UI만 없애고, 검수된 현장 문제를 원본 순서대로 문제 1·문제 2로 나열한다. 이 통합 버전의 실제 문제는 인화문 1개였다. `explorationRegionId`는 넓은 탐색 범위의 내부 기본값이며 지역 탭이나 별도 게임을 만들지 않는다. 지도에는 선택한 문제의 부분 사진과 범위만 표시하고 정답 후 다음 문제의 지도 또는 문제 목록으로 이동한다.

### v1의 잘못된 계수 근거 · 사용 중단

당시 전체 사진 Photo2에서 다음5개만 골라 세었으나, 피노키오 뒤에 가려진 작은 파란 무늬2개를 놓쳤다. 분홍색까지 섞은 이 목록은 전체 개수의 올바른 근거가 아니며 현재 정답 설명에 사용하지 않는다.

1. 피노키오 어깨 옆의 진한 파란색 무늬
2. 위쪽 청록색 무늬
3. 위쪽 옅은 분홍색 무늬
4. 가운데 옅은 민트색 무늬
5. 흰색 함의 문에 있는 분홍색 무늬

당시 흰 벽면과 흰색 함의 문에 그려진 여러 색을 함께 센다고 설명했고 `evidence: { "x": 74.1, "y": 48.2 }`를 사용했다. 새 사진에서 빠졌던 파란 무늬가 드러나 이 대상 범위·색상별 목록·마커를 그대로 유지할 수 없게 되었다. 무늬 한 덩어리를1개로 세는 원칙은 유지하되, v2는 **파란 계열만 포함하고 분홍색을 제외**한다.

v1 당시에는 사진 판독만 수행했고 사용자 확인은 받지 않은 상태였다. 이후 사용자가 새 근접 사진과 함께5개를 명시적으로 확인했으며, 그 자료로 아래 v2의 파란 계열5개를 다시 대조했다. 촬영 지점을 정밀 확인한 GPS 기록은 여전히 없고 지도는 기존 대표점 주변의 넓은 탐색 범위만 제공한다.

### v1 프로그램 검증 이력

콘텐츠 버전을 `unified-pinocchio-v1`로 갱신해 이전 단일 문제 진행 상태와 구분했다. 실제 문제2개·예시3개를 합친5개 데이터의 로컬 빌드가 성공했고, 전체72개 검사 중70개 통과·기존 AdGuard HTML 헤더/HEAD 관련2개 실패를 확인했다. 코드 `4349271`의 [CI 72개 검사·빌드·배포](https://github.com/ezid007/GDG_Incheon/actions/runs/34673636479)는 모두 통과했다. 당시 브라우저에서 문제 연결·사진 전환·오답·힌트·정답 후 전경과 공개390px/로컬320px 화면을 확인했다. 이 기록은 당시 프로그램 동작을 확인한 것으로, 사진 판독 내용의 정확성이나 아래 수정 버전의 검증 완료를 뜻하지 않는다.

## 피노키오 계수 기준 정정 · unified-pinocchio-v2

사용자가 새 근접 사진 `1-Photo-1.jpg`를 보내며 **5개라고 명시적으로 확인**했다. 새 사진은 피노키오 팔 뒤의 작은 무늬까지 보여주므로 이전 전경보다 판독 근거가 분명하다. v1은 분홍색을 포함해 일부5개만 골라 셌고 작은 파란 무늬2개를 놓쳤다. 정답 숫자5가 같더라도 이전 설명은 정확하지 않았으므로 질문·힌트·해설의 범위를 파란 계열로 명확히 바로잡았다.

### 현재 기준: 파란 계열5개

**옅은 하늘색을 포함한 파란 계열만 세고 분홍색은 제외한다.** 갈라진 꼬리선은 나누지 않고 무늬 한 덩어리를1개로 센다. 새 정답 사진에서 확인한 다섯 위치는 다음과 같다. 백분율은 사진상의 대략적인 관찰 위치이며 GPS 좌표가 아니다.

| 무늬 | 새 사진에서의 대략 위치 |
|---|---|
| 팔 뒤 작은 파란 무늬1 | x30%, y60% |
| 팔 뒤 작은 파란 무늬2 | x38%, y57% |
| 흰 배관 뒤 큰 파란 무늬 | x49%, y51% |
| 오른쪽 옅은 하늘색 무늬 | x66%, y41% |
| 위쪽 지붕 부근의 파란 무늬 | x64%, y24% |

보기는 A3개·B4개·C5개·D6개를 유지하고 정답은 C5개, 원본의 1부터 시작하는 번호는3이다. 사용자 확인과 새 사진이 일치하며, 별도로 보이는 분홍색 무늬를 파란 계열에 포함하지 않는다. 이는 사용자가 새 사진과 함께 개수를 확인한 기록이며 정밀 촬영 위치나 GPS 정확도를 인증한 기록은 아니다.

### 정답 사진 교체

v2 당시에는 1차에 최초 Photo3, 2차에 최초 Photo1을 사용했다. 이 두 역할은 이후 사용자 지시로 대체되었으므로 현재 역할로 해석하지 않는다. v1의 최초 Photo2 전경은 정답 사진 역할을 종료하고, 마지막으로 받은 벽면 근접 사진을 정답 자료로 사용하는 변경은 현재도 유지한다.

- 원본 복사 경로: `apps/golmok-detective/data/quiz-images/pinocchio-clouds/answer-photo.jpg`
- 공개 자산: `apps/golmok-detective/public/assets/field-pinocchio-answer.jpg`
- 정답 사진 근거 마커: `evidence: { "x": 49.5, "y": 51.5 }`

교체된 정답 사진은 정답 확인 후에만 공개하고 지도·1차 힌트에 넣지 않는다. 이전 정답 사진의 내용과 v1 SHA 검증은 역사 기록이며 새 사진 일치 검사를 대신하지 않는다. 내부 Songwol 대표 영역 반경110m는 유지하고 새 GPS 위치를 만들어 넣지 않는다.

### v2 검증 이력

콘텐츠 버전을 `unified-pinocchio-v2`로 갱신해 이전 설명과 진행 상태를 구분했다. 당시 빌드 성공, 로컬72개 중70개 통과·기존 AdGuard 관련2개 실패, 새 정답 원본·소스·공개 자산 SHA 일치와 Chrome390px 정답·확대·2+1+1+1 해설을 확인했다. 코드 `8c45c77`의 [CI72개 검사·빌드·배포](https://github.com/ezid007/GDG_Incheon/actions/runs/34673933342)도 성공했다. 이 기록은 이후의 세로 카드와 사진 역할 변경을 검증한 것은 아니다. 사용자 확인5개와 사진상의 파란5개는 콘텐츠 근거이며 현장 GPS 정확도와 구분한다.

## 세로 문제 카드와 최종 사진 역할 · scroll-pinocchio-v1

사용자가 문제를 가로로 전환하지 않고 **모든 문제 카드를 세로로 스크롤해 보도록** 요청했다. 공용 지도는1개이고, 실제 문제2개의 카드마다 장소 찾기 사진·안내·일반 도착·시연 버튼을 둔다. 실제 퀴즈 화면도 사진 다음에 질문·선택지가 세로로 이어진다. 문제별·현장/시연별 진행 분리와 정답5개는 유지한다.

최종 사진 역할은 사용자의 명시적인 순서에 맞춰 다음처럼 정정했다. 앞선 ‘파란 확대 사진으로 먼저 찾고 피노키오 근접 사진으로 푼다’는 해석은 더 이상 사용하지 않는다.

| 단계 | 사용자 자료와 실제 내용 | 원본 복사 경로 | 공개 자산 |
|---|---|---|---|
| 1차 장소 찾기 | 최초 Photo1: 피노키오·하트가 보이는 크롭 근접 사진 | `data/quiz-images/pinocchio-clouds/part-photo.jpg` | `assets/field-pinocchio-clue.jpg` |
| 도착 후 2차 문제·오답·힌트·확대 | 최초 Photo3: 파란 구름 무늬만 확대한 사진 | `data/quiz-images/pinocchio-clouds/quiz-photo.jpg` | `assets/field-pinocchio-quiz.jpg` |
| 정답 후 해설·확대·완료 | 마지막으로 받은 사용자 확인 벽면 사진: 파란 계열5개 판독 가능 | `data/quiz-images/pinocchio-clouds/answer-photo.jpg` | `assets/field-pinocchio-answer.jpg` |

원본 경로는 `apps/golmok-detective/` 기준이다. `part-photo`와 `quiz-photo`의 소스·공개 복사본 내용 및 대체 설명을 최종 역할에 맞춰 서로 바꿨고, 정답 사진은 v2의 최신 사진을 유지한다. 그림을 다시 생성하거나 사진에 새 무늬를 추가하는 변경이 아니다. 파란 계열만 세고 분홍색을 제외하는 질문·5개 정답·근거 마커49.5%,51.5%는 유지한다. 지도/장소 찾기 카드에 2차 파란 확대 사진이나 정답 벽면 사진을 먼저 넣지 않는다.

코드 `de8b695`의 [Actions34674323476](https://github.com/ezid007/GDG_Incheon/actions/runs/34674323476)에서 빌드·73개 검사·Pages 배포가 모두 성공했다. 로컬은73개 중71개 통과, 기존 AdGuard 응답 변경2실패이며 CI에서는 재현되지 않았다. 지도 UI19개 전부 통과. 로컬320/390/1280px에서 세로 카드와 사진·질문 상하 배치, 가로 넘침 없음, 공용 지도 전환·시연·정답 사진 확대를 확인했다. 공개390px에서 두 카드와 피노키오 크롭→도착→파란 무늬→5개 정답 후 최신 벽사진을 확인했다. 실제 현장 GPS 정확도는 별도 미검증이다. 사용자 원본·source·public의 각 사진 SHA-256 일치도 확인했다.

## 사진 파일명과 실제 내용

원본 파일명에 붙은 `original`·`hint`만으로 사용 시점을 판단하면 정답 사진이 먼저 노출된다. 아래처럼 실제 내용을 확인해 별도의 공개 자산 이름으로 복사했다. 원본 사진의 픽셀·파일 내용은 수정하지 않았다.

| 원본 자료 | 실제 사진 내용 | 게임 자산 | 공개 시점 |
|---|---|---|---|
| `raw/missions/gate_original.jpg` | 기둥 위 금빛 조각상을 확대한 사진. 중앙 현판은 보이지 않음 | `assets/field-gate-detail.jpg` | 문제와 찾아가는 단서 |
| `raw/missions/hint_statue_surroundings.jpg` | 중앙 현판의 `仁華門`이 보이는 관문 전체 사진 | `assets/field-gate-answer.jpg` | 정답 확인 후 근거·해설 |

전체 사진은 힌트·탐색 지도·도착 전 안내에 쓰지 않는다. 문제 사진의 대체 설명과 힌트에도 정답 이름을 먼저 적지 않았다. 힌트는 현장에서 시선을 돌릴 부분만 안내한다. `evidence: { "x": 48.5, "y": 44.5 }`는 **정답 확인용 전체 사진**에서 현판 중심을 표시하는 백분율이며, 문제 사진의 좌표나 GPS 좌표가 아니다.

정답 데이터와 사진은 정적 웹 배포 파일에 포함된다. 화면상 공개 시점을 구분하는 체험 게임이며, 소스 확인에 대한 정답 비밀 보장을 제공하지 않는다.

## 좌표의 출처와 범위

```json
{
  "explorationRegionId": "chinatown",
  "geoCoordinates": {
    "latitude": 37.473045,
    "longitude": 126.6188592
  }
}
```

좌표는 팀원 자료의 `geo_coordinates`를 그대로 옮긴 참고 메타데이터다. 관문 위치를 현장에서 정밀 측량한 값으로 검증한 것은 아니다. 한중문화관 인근을 포함하는 **넓은 탐색 구역의 중심을 잡는 용도**로만 사용하며, 정확한 정답 핀·도착 인증·자동 정답 해제로 사용하지 않는다. 사용자에게는 구역 안에서 사진의 조각상을 직접 찾아보도록 안내한다.

## 데이터 반영과 검증

최초 반영 시 기존 JSON에 이 현장 미션과 가상 미션 3개를 결합했다. 현재는 아래의 팀원 소스 통합 방식으로 전환하여 `quiz.js`와 `quiz-support.json`을 사용한다. 콘텐츠 버전은 `field-v2`이며 이전 예시 버전의 진행 상태와 구분한다.

확인 항목:

- 원본 사진 2장과 공개 복사본 2장의 SHA-256이 각각 일치한다.
- 현장 선택지는 서로 다른 4개이며 정답은 첫 번째 보기의 ID `a`와 일치한다.
- 문제 이미지와 정답 확인 이미지를 별도 경로로 지정했다.
- 선택지·사진·현판 글자를 대조했으며, 기존 초안의 다른 관문 정답과 역사 서술을 가져오지 않았다.
- 브라우저에서 문제·오답·힌트 상태는 부분 사진을 유지하고, 정답 후에만 전체 사진·근거가 나오는 것을 확인했다. 완료·새로고침 복원과 시연 저장 분리도 확인했다. 공개 배포 상태는 배포 기록에서 확인한다.

새 외부 API, 모델, 환경 변수, 패키지 설정은 없다. 후속 미션도 같은 기준으로 검수하고 자료 ID·사진 공개 시점·정답 근거·좌표의 확인 수준을 기록한다.

## 팀원 문제 사진 추가 · d6e37e6

현재 자료는 `apps/golmok-detective/data/quiz.js`와 `data/quiz-images/inhwamun/`에도 정리되어 있다. `part-photo.jpg`와 `answer-photo.jpg`는 기존 검수 복사본과 각각 SHA-256이 일치한다. 새 `quiz-photo.jpg`는 현판 글자만 물음표로 가린 사진이며, `public/assets/field-gate-quiz.jpg`로 픽셀 변경 없이 복사했다.

| 시점 | 데이터 필드 | 사용하는 사진 |
|---|---|---|
| 1차 장소 찾기 | `image` / `imageAlt` | 조각상 부분 사진 |
| 도착 후 2차 질문·오답·힌트·확대 | `quizImage` / `quizImageAlt` | 현판을 물음표로 가린 퀴즈 사진 |
| 2차 정답 후 해설·확대·완료 | `answerImage` / `answerImageAlt` | 현판 글자가 보이는 원본 전체 사진 |

지도에는 2차 퀴즈 사진과 정답 사진을 내장하지 않는다. 자동 검사와 브라우저에서 사진별 공개 시점을 확인했고, 버전을 `field-v2`로 올려 이전 진행 상태와 구분했다. `hintPhoto`는 파일 이름만 보고 자동으로 노출하지 않으며 후속 추가 시 내용을 검수한다.

## 팀원 문제 소스 통합

팀원의 정리 커밋에 따라 `missions.json`은 사용하지 않는다. `load-quiz.mjs`는 `quiz.js`의 질문·선택지·좌표를 읽고 `quiz-support.json`의 검수 정보(단서/문제/정답 사진 설명·해설·근거 좌표·검수 정답)와 결합한다. 팀원 형식의 `correctAnswerIndex`는 1부터 시작하는 보기 번호로 해석하고, 해당 보기의 글자가 검수 정답과 같은지 확인한다. 원본 세 사진과 공개 복사본이 다르거나 새 문제가 아직 검수 목록에 없으면 빌드를 중단한다. 사진 이름만으로 힌트 공개 여부를 결정하지 않는다.

## 단일 지도 통합 · unified-v1

출제자가 제공한 질문·네 선택지·사진·정답은 유지한다. 차이나타운과 동화마을을 따로 고르는 UI만 없애고, 검수된 현장 문제를 원본 순서대로 문제 1·문제 2로 나열한다. 현재 실제 문제는 인화문 1개다. `explorationRegionId`는 넓은 탐색 범위의 내부 기본값이며 지역 탭이나 별도 게임을 만들지 않는다. 지도에는 선택한 문제의 부분 사진과 범위만 표시하고 정답 후 다음 문제의 지도 또는 문제 목록으로 이동한다.

## 새 동화마을 자료 · 검수 대기

팀원 `ce550e5` 이후 공유된 `data/tale-town-1.json`과 저장소 루트 `public/images/quiz/tale-town-1/` 사진2장을 확인했다. 부분 사진은 양철 나무꾼, 힌트 사진은 같은 성 외관의 전경이며 파일은 원본 상태로 보존한다. 정답 해설은 가방을 명시하지만 `correctAnswerIndex: 3`은 현재 `quiz.js`의 1부터 시작하는 기준과 다르므로 그대로 가져오면 우산으로 잘못 처리된다. 가방 의도를 사용자에게 확인 중이다. 두 사진은 주변 물체 전체를 담지 않아 정답 근거 사진으로 확정하지 않았다. 제공 좌표는 현재 지도·수집도로 범위 밖이고 이미지에는 GPS 메타데이터가 없어 촬영 위치도 확인이 필요하다. 현재 공개된 실제 문제1개에 이 검수 대기 자료를 포함하지 않는다.

후속 확인: 팀원 `22032c9`의 [문제 통합 계획](work-plans/2026-09-12-tale-town-quiz-merge.md)에서 **4번 가방**과 수정한 참고 좌표 `37.477661,126.620583`을 명시했다. 이 계획으로 출제자의 번호 기준은 해소되었으며 사용자 추가 확인은 필요 없다. 이는 구현 완료의 증거는 아니므로 `quiz.js`와 검수 정보·사진의 실제 연결 및 공개 배포는 별도로 확인한다. 현재 공개 목록은 실제 문제1개다.

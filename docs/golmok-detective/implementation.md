# 골목탐정 구현·협업 안내

확인 날짜: 2026-09-12

## 현재 목표와 범위

현장 사진을 자세히 관찰하며 장소의 특징을 발견하는 짧은 모바일 웹게임을 만듭니다. 기본 구성은 3개 미션이며, 시간이 부족하면 1개 미션을 시작부터 완료까지 정상 작동하는 범위로 마무리할 수 있습니다.

현재 콘텐츠는 **가상 예시 SVG 3개**입니다. 실제 인천 현장 사진이나 장소의 사실로 소개하지 않습니다. 현장 관찰 자료를 확보한 뒤 사진과 질문·정답 근거를 함께 교체해야 합니다.

이번 범위에는 회원가입, 데이터베이스, GPS 인증, 방문자 파일 업로드, 플레이 중 AI 호출을 포함하지 않습니다. 현장 자료를 바탕으로 사람이 Agent에게 제작을 지시하고 결과를 확인하는 방식입니다.

## 사용자 흐름

| 단계 | 사용자 행동 | 서비스 동작 |
|---|---|---|
| 시작 | 시작 버튼 선택 | 첫 번째 미션 표시 |
| 관찰 | 그림과 질문 읽기 | 현재 미션과 진행 상황 표시 |
| 선택 | 답 선택, 필요하면 힌트 열기 | 선택 상태와 힌트 표시 |
| 확인 | 정답 확인 | 오답이면 재선택, 정답이면 근거 표시 |
| 이동 | 다음 미션 선택 | 선택·피드백·힌트 초기화 후 다음 문제 표시 |
| 완료 | 마지막 정답 확인 후 이동 | 완료 화면 표시, 다시 시작 제공 |

정답 확인 전에 다음 문제로 건너뛸 수 없습니다. 이미 정답을 확인한 문제에서는 답을 변경할 수 없으며, 확인 버튼을 반복해도 진행도가 중복으로 증가하지 않습니다.

## 실행과 수정

검증 환경은 Node.js 22/24이며 외부 패키지를 설치하지 않습니다. 모든 명령은 저장소 루트에서 실행합니다.

```sh
# 게임 화면 생성
node apps/golmok-detective/build.mjs

# 기본 포트 4179에서 시작
node apps/golmok-detective/serve.mjs

# 필요한 경우 포트 변경
node apps/golmok-detective/serve.mjs --port 4180

# 전체 로컬 검사
node --test apps/golmok-detective/tests/*.test.mjs
```

기본 접속 주소는 [http://127.0.0.1:4179](http://127.0.0.1:4179)입니다. 미션 또는 코드를 수정한 뒤 다시 빌드하고 브라우저를 새로고침합니다. 서버는 요청할 때마다 현재 파일을 읽고 캐시를 남기지 않도록 응답합니다.

## 현장 미션을 작성하는 방법

한 미션은 사진 한 장에서 확인 가능한 특징을 중심으로 만듭니다. 같은 장소에서도 서로 다른 관찰 포인트가 명확하면 여러 미션을 구성할 수 있습니다.

| 필드 | 작성 내용 |
|---|---|
| `id` | 미션을 구분하는 고유 ID |
| `sourceId`, `sceneKind` | 자료 식별자와 예시 여부 |
| `placeLabel` | 장소를 설명하는 짧은 이름 |
| `image`, `imageAlt` | 검토된 그림 경로와 이미지 설명 |
| `question` | 그림에서 답을 확인할 수 있는 질문 |
| `options`, `answerId` | 선택지와 정확히 일치하는 정답 ID |
| `hint` | 정답을 찾을 관찰 위치나 방법 |
| `explanation`, `evidenceQuote` | 정답의 이유와 실제 관찰 근거 |
| `evidence` | 단서 위치를 표시할 때 사용하는 좌표 |

최상위 `version`은 저장된 진행 상태의 호환성을 구분합니다. 미션 순서나 정답처럼 플레이 결과에 영향을 주는 내용을 바꾸면 버전도 갱신합니다. 오래된 버전의 저장 상태는 처음부터 시작하도록 처리합니다.

사진을 제공할 때에는 장소 이름, 직접 관찰한 특징, 사진의 어느 부분이 근거인지를 함께 남깁니다. 실제 자료 반영 시에는 예시 표시도 함께 검토합니다. 새로운 사진 파일은 서버의 공개 허용 목록에 명시적으로 추가하고 확인해야 합니다.

## 상태와 저장 복원

상태 모듈은 다음 세 함수를 제공합니다.

- `initialState(missions)`: 시작 화면과 빈 진행 상태를 반환합니다.
- `transition(state, action, missions)`: 사용자 행동에 따른 새 상태를 반환합니다.
- `restoreState(raw, missions, version)`: 저장 상태를 검사하고, 잘못되었거나 버전이 다르면 처음 상태로 돌립니다.

화면은 `start`, `mission`, `complete`로 구분합니다. 진행도는 순서대로 해결한 미션 ID 목록으로 관리합니다. 완료 상태에서는 마지막 미션 인덱스를 유지하고 해결한 개수가 전체 개수와 같아집니다.

저장 복원은 존재하지 않는 미션이나 선택지, 중복·누락·순서가 어긋난 정답 기록, 잘못된 화면과 인덱스, 정답 여부가 서로 맞지 않는 상태를 거부합니다. 상태 변경과 복원은 전달받은 원본 객체를 수정하지 않습니다.

브라우저의 같은 탭에서 진행을 복원하는 것이 목표입니다. 기기 간 동기화 기능은 없습니다. 저장이 차단된 환경에서의 안내와 실제 화면 복원은 브라우저 검증 항목에 포함합니다.

## 서버와 외부 접속

서버는 기본적으로 `127.0.0.1:4179`에 연결합니다. 포트 인수는 1~65535 범위의 정수만 허용합니다. 외부에서는 [임시 HTTPS 게임 주소](https://machines-ambien-wear-arab.trycloudflare.com/)로 접속합니다. 운영 방법과 유지 조건은 [공개 운영 안내](deployment.md)에 기록합니다.

서버가 제공하는 파일은 `index.html`과 검토된 SVG 3개뿐입니다. 루트 주소 `/`는 `index.html`을 보여줍니다. GET과 HEAD만 허용하며, 공개 목록에 없는 경로는 파일 존재 여부와 관계없이 404로 처리합니다. 문서, 로그, 환경 변수 파일, 원본 첨부 폴더를 이 게임 서버로 제공하지 않습니다.

임시 터널로 공개하는 경우 게임 서버·터널·네트워크가 유지되어야 접속할 수 있습니다. 최종 제출 전에는 휴대전화 네트워크에서 주소와 전체 게임 흐름을 다시 확인하고 화면 녹화나 캡처 백업을 준비합니다.

전체 자동 검사는 20개 중 18개 통과·2개 실패입니다. 공개 주소 브라우저에서 수집한 오류·경고 로그는 없었습니다. 모바일 그림의 고정 높이 때문에 생겼던 빈 공간은 자동 높이로 수정했고, 회전 장식 때문에 생겼던 가로 넘침은 그림의 여유 폭을 조정하여 해결했습니다.

서버 검사에서는 로컬 AdGuard가 HTML 응답의 `Content-Length`를 제거하고 CSP를 변경했습니다. HEAD 요청에는 잘못된 chunked 응답이 나타나 클라이언트 파싱이 실패했습니다. 서버 핸들러가 생성하는 원래 GET/HEAD 헤더, 바이트 길이와 HEAD 무본문 처리는 별도 검사에서 정상임을 확인했습니다. `no-transform` 응답 지시로도 현상이 바뀌지 않았으며 필터 설정은 변경하지 않았습니다. 네트워크 검사 실패 두 건은 숨기거나 건너뛰지 않고 남겨두었습니다.

## 협업과 발표 준비

현장 관찰 담당은 사진과 근거를, 문제 작성 담당은 질문·힌트·해설을, 제작 담당은 반영과 검증 결과를 준비합니다. 팀 규모에 맞게 역할을 겸할 수 있습니다. 각자 Agent에게 무엇을 지시했고 어떤 결과를 확인·수정했는지도 짧게 기록합니다.

발표에서는 현장의 관찰이 어떤 게임 기능으로 이어졌는지 먼저 설명하고 실제 플레이 화면을 보여줍니다. 사람별 역할과 Agent의 역할을 함께 설명할 수 있도록 준비합니다. 기능을 늘리는 것보다 한 미션이라도 처음부터 끝까지 정상 작동하는 경험을 우선합니다.

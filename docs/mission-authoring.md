# 현장 4지선다 문제 전달 양식

확인 날짜: 2026-09-12 · 적용: 차이나타운 골목탐정 정적 웹, `field` 미션 · 콘텐츠 버전 `unified-v1`

팀원이 작성한 문제를 검수한 뒤 게임에 반영한다. 현재 관문 문제 1개를 실제 목록에 넣고, 예시 3개는 보존하되 실제 목록에 넣지 않는다. 차이나타운/동화마을 탭 없이 **한 지도에서 실제 문제를 문제 1·문제 2 순서로 선택**한다. 자료가 준비되기 전에는 실제 장소의 문제·정답을 임의로 만들지 않는다.

한 문제는 `1차 부분 사진·넓은 탐색 범위 → 도착 → 2차 가림 사진·4지선다 → 정답 사진·해설`로 구성한다. 정답 후에는 다음 문제의 장소 찾기 지도로 이동하거나 문제 목록으로 돌아간다. 1차와 2차를 서로 다른 문제로 등록하지 않는다.

## 한 문제에 필요한 자료

아래 내용을 복사해 `docs/quiz-이름.md`에 작성하고 사진은 `apps/golmok-detective/data/quiz-images/이름/`에 함께 올린다. 현재 팀원 자료는 `apps/golmok-detective/data/quiz.js`와 `data/quiz-images/inhwamun/`에 있다. 초안이 곧 검수 완료를 뜻하지는 않는다.

```text
미션 이름:
고유 문제 ID: 영문 소문자·숫자·하이픈 사용
문제 목록의 희망 순서:
장소 이름(운영진 확인용):
넓은 탐색 구역: 예) 안내지도에서 입구를 지나 첫 골목 주변
검수한 탐색 범위(선택): 중심 위도·경도·반경(m) 및 근거. 없으면 기존 대표 영역 사용
찾아가는 단서: 정답 장소를 정확한 핀으로 알려주지 않는 짧은 문장
1차 장소 찾기 부분 사진 파일:
2차 현장 퀴즈 가림 사진 파일:
사진 설명: 정답을 미리 말하지 않는 설명
질문:
A:
B:
C:
D:
정답: A / B / C / D 중 하나
정답 근거: 실제 현장에서 어느 부분을 확인했는지
근거 위치: 정답 확인용 사진의 어느 부분인지
확인 사진 파일: 필요한 경우 별도의 원본 사진
해설:
추가 관찰 안내: 정답 자체를 공개하지 않는 문장
확인 날짜와 현장 확인 여부:
```

- 서로 구분되는 선택지 **4개**, 정답 **1개**가 필요하다. 같은 말을 반복한 선택지는 넣지 않는다.
- 질문으로 묻는 글자·이름·사진은 지도나 이동 안내, 힌트에서 먼저 공개하지 않는다. 원본 사진이 답을 보여주면 정답 확인용 자료로 구분해 전달한다.
- 넓은 탐색 범위는 지도 위 위치 설명이나 표시한 참고 사진으로 전달할 수 있다. **GPS 좌표는 제출 필수가 아니다.** 기본 대표 영역을 쓸 수 있고, 문제별로 따로 검수한 범위가 있으면 중심·반경·근거를 함께 전달한다. 정답 핀이나 도착 인증 조건으로 쓰지 않으며 확인되지 않은 좌표를 작성하지 않는다.
- 사진에 나온 장소와 질문의 정답이 일치하는지 확인한다. 특히 여러 관문의 이름·현판 글자를 혼동하지 않는다.
- 지나가는 사람의 얼굴, 연락처 등 불필요한 개인정보가 포함된 사진은 그대로 공개하지 않는다.

## 게임 반영과 검증

문제 원본은 `apps/golmok-detective/data/quiz.js`, 검수·표시 정보는 `data/quiz-support.json`이며, 검토된 이미지는 `apps/golmok-detective/public/assets/`에 둔다. `sceneKind: "field"`는 정확히 4개 선택지를, 기존 `example`은 3개 선택지를 받는다. 선택지의 ID·표시는 고유해야 하며 `answerId`는 해당 ID 하나와 정확히 일치해야 한다. `evidence.x`, `evidence.y`는 사진에서 근거를 표시하는 0~100 범위의 백분율이며 GPS 좌표가 아니다.

실제 문제의 순서와 사진 공개 시점을 확인한 뒤, 순서·선택지·정답이나 저장 방식이 바뀌면 검수 파일의 최상위 `version`도 갱신한다. 이번 단일 지도·문제별 진행 통합 버전은 `unified-v1`이며 기존 출제 문구·사진·정답은 유지한다. 이미지 경로는 `assets/영문소문자-파일명.jpg`와 같은 형식을 사용한다. 지원 형식은 SVG/JPG/JPEG/PNG/WebP다. 빌드 때 사진은 게임 HTML에 내장된다. 정답 데이터도 브라우저에 포함되므로 현장 탐색을 돕는 체험 게임의 용도다.

`explorationRegionId`의 `chinatown`·`songwol`은 **기존 대표 영역을 찾아 지도에 배치하는 내부 정보**다. 문제 목록을 지역별로 나누거나 사용자에게 지역 탭을 보여주는 값이 아니다. 빌드 시 검수한 `field` 문제만 순서대로 `MAP.quizzes`에 구성한다.

문제별로 검수한 영역이 있으면 선택 항목 `explorationArea`로 기본 대표 영역을 덮어쓸 수 있다. 없으면 `explorationRegionId`에 대응하는 기존 대표 영역을 사용한다. 아래 값은 기존 한중문화관 대표 영역을 표현한 예시이며 정확한 관문 좌표가 아니다. 문제별로 바꾸려면 출처와 현장 검수 근거를 함께 남긴다.

```json
{
  "explorationArea": {
    "latitude": 37.4735836355535,
    "longitude": 126.618776323953,
    "radiusMeters": 135
  }
}
```

1차 단서 사진은 `image`·`imageAlt`, 2차 문제 사진은 선택 쌍 `quizImage`·`quizImageAlt`로 구분한다. 2차 사진을 생략하면 기존 자료와의 호환을 위해 단서 사진을 사용하지만, 현장 문제를 전달할 때는 가림 사진을 함께 준비한다. 별도 정답 사진은 `answerImage`와 `answerImageAlt`를 함께 지정하며, `evidence`는 그 정답 사진 기준으로 작성한다. 파이썬 등으로 전달할 때도 사진을 함께 저장소에 올리고 개인 PC 절대 경로 대신 상대 경로를 적는다. 정답 번호는 ‘1번’인지 ‘0부터 시작하는 인덱스’인지 명확히 쓰며, 웹에는 `answerId`로 변환한다.

문제 ID는 해당 문제의 지도·2차 퀴즈·시연·진행 저장을 연결하므로 한 번 공유한 ID를 이유 없이 바꾸지 않는다. 현재 실제 문제의 주소 형식은 다음과 같다.

- 장소 찾기: `map.html?quiz=inhwamun-plaque`
- 현장 도착 후 2차: `./?play=field&quiz=inhwamun-plaque`
- 발표용 도착 시연: `./?demo=arrival&quiz=inhwamun-plaque`

새 링크는 `quiz`를 사용한다. 예전 `region` 링크는 호환용으로 남길 수 있지만 새 문제를 안내할 때 지역별 주소를 다시 만들지 않는다. 진행은 문제별·현장/시연별로 분리한다.

```sh
node apps/golmok-detective/build.mjs
node --test apps/golmok-detective/tests/*.test.mjs
```

검수자는 휴대전화에서 문제 선택→부분 사진과 범위→도착→가림 사진·보기 4개→오답 재시도/정답 해설→다음 문제의 지도 또는 목록까지 확인한다. 네 번째 선택지가 정답인 테스트 자료도 사용해 보기 처리를 검사하고, 실제 문제와 예시가 섞이지 않는지, 문제별·시연별 새로고침 복원이 서로의 기록을 덮어쓰지 않는지 확인한다. 원본 자료의 업로드와 공개 게임 반영은 구분하며, 게임 HTML 생성과 배포가 완료되어야 플레이 화면에 나타난다.

`unified-v1` 코드 `f12fe15`의 CI72개 검사·빌드·배포가 모두 성공했다. [이번 배포 검사 기록](https://github.com/ezid007/GDG_Incheon/actions/runs/34673092862) 로컬은 지도18개·세션10개 통과, 전체72개 중70개 통과·기존 AdGuard 관련2개 실패였다. 공개 Chrome에서 문제1의 지도→도착→가림 사진·보기4개→정답 원본→완료→문제 목록과 별도의 시연0/1 진행을 확인했다. 로컬320·1280px와 공개390px에서 가로 넘침이 없었다. 현재 공개된 실제 문제는 검수한1개이며, 추가 제출 자료는 검수 완료 후 반영한다. 현장 휴대전화의 GPS 정확도는 아직 미검증이다.

문서 근거: 이 저장소의 `build.mjs`, `mission-validation.mjs`, `game-state.mjs`와 팀원 공유 자료 경로를 확인했다. 새 외부 API나 패키지 설정은 필요하지 않다.

### 팀원 JavaScript 자료와 웹 필드 대응

| 팀원 `quiz.js` | 웹에서 사용하는 값 |
|---|---|
| `partPhoto` | 검수된 `image`와 같은 사진: 1차 장소 찾기 |
| `quizPhoto` | 검수된 `quizImage`와 같은 사진: 2차 문제 |
| `answerImage` | 검수된 `answerImage`와 같은 사진: 정답 확인 후 |
| `quizText`, `choices` | 질문과 번호 접두어를 정리한 보기 4개 |
| `correctAnswerIndex` | 현재 팀원 양식은 보기 번호 1~4, 검수 정답 글자와 다시 대조 |
| `geoCoordinates` | 참고 좌표. 도착 인증에 사용하지 않음 |

`quiz-support.json`의 해당 검수 항목과 실제 공개 사진을 함께 갱신해야 새 자료를 빌드할 수 있다. 파일 이름만 같은 다른 사진, 검수하지 않은 정답 변경, 아직 검수 목록에 없는 새 문제는 자동 공개하지 않는다.

# 구현 안내

확인일: 2026-09-13 · 콘텐츠 버전: `unified-three-missions-v1` · Node.js 22/24 · 런타임 추가 의존성 없음

## 구성과 동작

차이나타운 골목탐정은 HTML·CSS·JavaScript로 만든 정적 웹입니다. 소개 → 세로 문제 목록과 그림 지도 → 장소 도착 확인 → 4지선다 → 정답 해설 순서로 진행합니다. 인화문·피노키오·동화마을의 실제 문제 3개를 사용하며, 가상 예시 3개는 실제 목록에 섞지 않습니다.

개발 원본은 역할별 파일로 나누고, 빌드할 때 코드·데이터·사진을 게임과 지도 HTML에 내장합니다. 웹사이트는 별도 애플리케이션 서버 없이 정적 파일로 실행됩니다. Node는 제작·검사·로컬 미리보기에 사용합니다.

## 빌드 흐름

1. JSON과 사진 경로를 검증하고, `expectedAnswer`와 일치하는 보기의 `id`를 `answerId`로 변환합니다.
2. 게임은 상태 코드·세션 코드·사진·QR을, 지도는 장소 찾기 사진·탐색 범위·위치 코드를 조립합니다.
3. `build-page.mjs`는 필요한 삽입 위치가 정확히 한 번 있는지 확인하고, 남은 자리표시자가 있으면 실패합니다.
4. 결과를 `public/index.html`, `public/map.html`에 저장합니다. 생성 파일도 현재 저장소에서는 함께 관리합니다.

JSON을 HTML에 넣을 때 `<`를 이스케이프하며, 파일 읽기 전에 상대 이미지 경로를 검증합니다. 스키마 클래스의 인스턴스는 로더에서 `structuredClone`을 거쳐 일반 데이터로 바뀝니다.

## 진행·사진·공유

일반 플레이와 발표 시연은 문제별 저장 키를 구분합니다. 콘텐츠의 순서·정답·선택지·저장 의미가 바뀌면 버전을 갱신하고 복원을 확인합니다. 사진은 `image` → `quizImage` → `answerImage`의 역할을 지킵니다. 정답 사진이 없는 문제에는 근거 지점을 표시하지 않습니다.

공유 창은 QR·기본 게임 주소·복사 버튼을 함께 표시합니다. QR은 기존 원본을 내장하며, 기본 공유 주소에는 현재 문제나 시연 쿼리를 붙이지 않습니다. 공유 미리보기 메타데이터도 같은 QR 사진을 사용합니다.

## 검증과 제한

실행 명령과 작업 순서는 [개발 작업 가이드](development-workflow.md), 미리보기와 배포 경계는 [실행·배포 문서](deployment.md)를 따릅니다.

GPS는 선택적인 탐색 보조이며 도착을 인증하지 않습니다. 위치를 저장하거나 서버로 전송하지 않습니다. 실제 현장 GPS 정확도와 동화마을 벽화 전체 근거 사진은 추가 확인 대상입니다. 정답은 정적 배포 파일에도 포함되므로 경쟁용 정답 은닉 시스템은 아닙니다.

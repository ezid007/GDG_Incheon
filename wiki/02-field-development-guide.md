# 02. 현장 개발 가이드 (Field Development Guide)

## 1. 오늘의 개발 모델 (Direct, Don't Code)
우리의 역할은 **"코드를 직접 작성하는 개발자"**가 아니라 **"Agent에게 일을 맡기고 결과를 판단하는 사람"**입니다.

```
[01. 문제 발견] ➔ [02. 사진·상황 전달] ➔ [03. 개발 지시] ➔ [04. 결과 확인] ➔ [05. 수정 요청]
```

---

## 2. 단일 HTML 기반 개발 전략
현장에서는 외부에서 노트북의 `localhost`에 직접 접속하기 어렵습니다. 따라서 **단일 HTML(Single File HTML)** 또는 즉시 배포 가능한 형태로 개발하는 것을 추천합니다.

* **HTML 파일 압축 전송:** 각 기능 작업이 완료되면 HTML 파일을 포함한 zip 형태로 전송받아 모바일 브라우저에서 바로 열람/확인.
* **배포 서비스 활용:** Vercel, Tailscale, GitHub Pages 등을 활용할 수 있다면 SPA(React, Svelte 등) 개발도 가능.

---

## 3. 현장 관찰 기반 보고 요령 (Observe Before Building)
무작정 "서비스 만들어줘"라고 지시하기보다, 현장 사진과 구체적인 상황을 먼저 전달해야 Agent가 정확한 문제를 파악합니다.

### 📷 보고 체크포인트
1. **누가 (Who):** 대상 사용자 (예: 외국인 관광객, 길거리 간식 줄을 선 가족 등)
2. **어디에서 (Where):** 구체적인 장소 (예: 신포시장 입구, 개항장 거리)
3. **어떤 불편을 겪고 있는가 (Pain Point):** 메뉴판 언어 장벽, 대기 시간 지루함 등

---

## 4. 범위 좁히기 (Narrow The Scope)
한 번에 모든 것을 만들려고 하면 에이전트가 복잡한 코드를 생성하다 실패할 수 있습니다. **단계별 지시**를 활용하세요.

1. **① 문제 분석:** "가장 큰 문제를 정리해줘. 아직 개발하지 마."
2. **② MVP 정의:** "3시간 안에 만들 최소 기능(MVP)을 최대 3개로 제안해줘."
3. **③ 구현 계획:** "가장 중요한 기능 1개의 구현 계획을 세워줘. 아직 파일 수정하지 마."
4. **④ 구현 및 검증:** "그 계획대로 구현하고 정상 작동 테스트까지 완료해줘."

---

## 5. 결과 검증 및 피드백 (Verify & Feedback)
Agent의 "완료 보고"가 실제 완료를 의미하지 않습니다. 모바일 관점에서 반드시 체크하세요.

### ✅ 검증 체크리스트
* [ ] 실제 페이지가 모바일 브라우저에서 정상 열리는가?
* [ ] 버튼 클릭 및 터치 인터랙션이 동작하는가?
* [ ] 입력 데이터가 정상 처리되는가?
* [ ] 모바일 화면 크기(반응형)에서 레이아웃이 깨지지 않는가?
* [ ] 새로고침해도 앱이 죽지 않는가?

### 🗣️ 효과적인 피드백 예시
* ❌ *“UI가 별로야. 예쁘게 만들어줘.”* (추상적)
* ✅ *“첫 화면에서 사용자가 무엇을 해야 하는지 모르겠어. 가장 중요한 버튼 하나만 강조하고 모바일 기준으로 수정해.”* (구체적)

---

## 6. 저장 및 복구 전략 (Save & Recover)
* 정상 작동되는 단계마다 반드시 **`git commit`**을 생성합니다.
* 문제가 발생하거나 코드가 꼬였을 때는:
  * *"마지막 정상 커밋 상태로 되돌려줘."*
  * *"시도한 방법과 실패 원인을 정리하고, 다른 해결 방법을 제안해줘."*
